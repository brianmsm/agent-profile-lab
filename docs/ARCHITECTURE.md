# Architecture, policy and public/private data boundaries

## Source-of-truth objects

1. **Harness contract** — version-pinned native roles, supported model selectors, reasoning effort, concurrency and role exclusions.
2. **Access identity** — published model identifier, provider offering, compatible authentication route and declared account-plan assumptions.
3. **Reference profile** — stored, human-reviewed combination of harness, portfolio, domain and objective. A decision record, not a recalculated score.
4. **Functional policy** — protective constraints on coordination, architecture, requirements, independent review and high-impact work.
5. **Workload scenario** — hypothetical calls per month and total tokens per call for each of 20 canonical functions.
6. **Evidence observation** — source-specific numeric metric only where the publisher's data rights and protocol metadata permit redistribution. Otherwise an attributed link without a cached score.

## Profile preservation

The public candidate includes **the same original 2,496 configurations and 33,414 executable assignment slots**, assembled from identical author-owned source decision shards and their SHA-256 manifest. The additional 16,224 historical SDD decisions stay retired, never executable.

The release manifest compares canonical SHA-256 digests of the complete routing structure and reference metadata before and after publication preparation. A mismatch blocks packaging. The 160 stored baseline strategies are also carried forward without reranking.

Evidence-linked candidate recipes retain their IDs, objective/domain admission rules, model choices, effort, role changes and stable evidence IDs. The 42 referenced external evidence records retain their models, metric names and protocol IDs but publish no third-party numerical scores. A missing value is labeled not redistributed, never zero.

## Browser delivery and trusted loading

The portable public snapshot provides compressed, content-addressed core and evidence transports through a SHA-256-validated manifest. The dashboard web worker verifies bytes and checksums before decompression, then checks profile contracts. No external publisher API requests are required to browse the release.

The numeric evidence table contains only approved license-reviewed BFCL cells. Other registered source references remain visible through direct publisher hyperlinks, even though their values cannot be downloaded from this package.

## Operational limits

- Quality eligibility precedes quota balancing; unsupported model routes are rejected.
- Static workloads are assumptions, not real provider token counters.
- Generated native files do not implement spend enforcement, provider login, automatic fallback execution, or human acceptance.
- Model-name aliases or public checkpoints do not verify actual gateway checkpoint identity.
- Equality of two profile configurations is not equality of observed quality, latency or cost.
- Future harnesses require native source contracts and their own validators.
